# VentoOS 当前实现审查说明与执行记录

- 审查日期：2026-04-25
- 审查方式：静态代码审查 + 定向证据核验
- 审查范围：web、native、native/fileprovider、docs/requirements
- 审查目标：找出当前系统实现中的问题、漏洞、未完成项，并形成按角色拆分的结论文档

## 1. 审查角色

- 系统设计开发工程师：关注功能闭环、交互链路、接口是否接通、占位实现是否暴露到用户路径
- 安全工程师：关注令牌处理、代理能力、明文凭证、下载链路、认证设计是否安全默认
- 架构师：关注边界划分、职责下沉、能力重复、可演进性与可维护性
- 测试质量工程师：关注可执行测试、测试边界、Mock 与真实实现偏差、关键模块覆盖率

## 2. 本次审查结论摘要

- 结论 1：系统外壳和部分基础设施已经成型，但多个核心业务路径仍存在明显“可见但未真正完成”的实现缺口。
- 结论 2：至少存在 2 类应优先处理的安全问题：令牌经 URL 传递，以及通用代理能力对外暴露但未在局部实现中体现出 allowlist 或最小权限约束。
- 结论 3：当前项目已经有前端组件级测试和部分 Rust 测试，但关键高风险模块的真实集成验证仍明显不足。
- 结论 4：部分模块已经跨越“占位”阶段进入“可被用户点击和调用”的阶段，因此问题已不再只是技术债，而是产品行为偏差和误导风险。

### Step 4. 扫描测试与验证空白

- 方法：检查 web/package.json、native/Cargo.toml、关键 crate 的 tests 目录，以及前端测试是否大量依赖 Mock。
- 发现：
  - web 已配置 Vitest，但很多测试以 mock API 为主。
  - native/crates/ventoos-api-client/tests 不存在。
  - native/crates/ventoos-mount/tests 不存在。
  - native/crates/ventoos-server/tests 仅见 comprehensive.rs，仍不足以覆盖前述 WebSocket 行为缺口。
  - native/fileprovider 未见独立测试目录。

### Step 5. 对关键证据做近邻代码核验

- 已核验的实现缺口：
  - SqlEditor 的保存动作仍为空实现。
  - TableDesigner 的保存动作使用 sleep 模拟，无真实 API 调用。
  - Kubernetes ResourceList 的批量删除仍为空实现。
  - SSH test_server 返回固定成功结果。
  - get_server_metrics 注释明确说明仍为 stub。

### Step 6. 对外暴露路径确认

- 已确认的调用链：
  - web/src/apps/api-client/api.ts 将代理 REST、WebSocket、MQTT 会话能力直接暴露给前端。
  - native/crates/ventoos-api-client/src/routes.rs 将这些代理能力映射为后端路由。
  - 因此，这些能力不是内部草稿代码，而是已经形成可调用接口。

### Step 7. 拆分子 Agent 并行修复

- 子 Agent A：修复 File Provider token 泄露与 API Client 代理目标限制。
- 子 Agent B：修复 SSH test_server 固定成功的问题，并补最小回归测试。
- 子 Agent C：修复 WebSocket 订阅管理缺失，补最小可观察的 AppMessage 失败回包。
- 主 Agent 补充收口：为前端 wsClient 与 taskService 增加 task_events 显式订阅与重连后重放订阅，避免后端订阅收口带来前端回归。

### Step 8. 修复后验证

- Rust 定向测试：
  - `cd native && cargo test -p ventoos-api-client --lib`
  - `cd native && cargo test -p ventoos-ssh --lib`
  - `cd native && cargo test -p ventoos-server --lib websocket`
- Rust 定向构建：
  - `cd native && cargo build -p ventoos-api-client -p ventoos-ssh -p ventoos-server`
- Rust 定向 clippy：
  - `cd native && cargo clippy -p ventoos-api-client -p ventoos-ssh -p ventoos-server --tests --no-deps -- -D warnings`
- 前端构建：
  - `cd web && pnpm build`

### Step 9. 验收结果摘要

- 已完成：
  - File Provider token 不再拼接到 URL，日志不再打印完整敏感路径。
  - API Client 的 REST/WebSocket/MQTT 入口增加静态目标限制，并补最小回归测试。
  - SSH test_server 改为真实连通性测试，不再固定成功。
  - WebSocket 订阅管理已落地，task_events 需要显式订阅；AppMessage 已支持插件 hook 与按 `app_id` 分发。
  - 数据库 SQL 保存、表结构保存与 Kubernetes 批量删除均已接入真实执行链路，不再是前端假实现。
  - SSH 服务器指标接口已接入真实 SSH 远程采集（CPU/内存/磁盘），不再返回 stub 响应。
  - VentoFS.zip 下载与嵌入解压前新增 SHA-256 完整性校验，并通过 mount 定向测试与 clippy。
  - WebDAV 需求文档已收口为安全默认值，改为优先 `webdavs://`，不再推荐在 URI 中携带用户名密码。
- 未完成：
  - 当前无，本轮既定修复项已完成收口。

## 4. 审查限制

- 本次未执行全量运行时联调，也未做动态渗透测试。
- 本次没有复核全局认证中间件，因此对于“是否已被全局鉴权兜底”的问题，只能给出模块级结论，不能替代端到端安全验收。
- 本次重点是实现问题与高价值风险，不追求穷尽全部低级别样式或代码风格问题。
