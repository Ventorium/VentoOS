VentoOS AI Assistant: 基于 Harness 架构的设计规约1. 核心哲学：The Harness Principle在 VentoOS 中，AI 不是一个简单的对话框，而是一个被 Harness（安全围栏/治理架构） 严格约束的系统调用者。引擎与底盘分离： LLM 负责逻辑推理（引擎），Rust 编写的 Harness 负责执行验证与资源隔离（底盘）。最小化先验，最大化结构： 不依赖冗长的 System Prompt 灌输规则，而是通过系统层级的 API 限制和策略引擎来约束行为。2. 系统架构分层 (Layered Harness Architecture)根据 Harness 思路，系统分为四层，每一层对上一层进行约束：L1: Kernel Layer (Rust / VFS / PTY)职责： 提供原生的原子操作。核心： 重构 pi-mono 逻辑，使用 Rust 实现高性能的虚拟终端 (PTY) 和 虚拟文件系统 (VFS)。约束： 只有通过 Rust 安全检查的路径和指令才能被透传。L2: Harness Layer (The Guardrail)职责： 拦截与治理。功能：指令审计： 对 bash 工具进行实时解析，拦截高危指令（如 rm -rf / 无参数调用）。权限注入： 根据用户当前的 Teleport 状态，动态注入对应的 K8s/DB 凭证，AI 无法感知明文密钥。L3: Cognitive Layer (Agent-Loop)职责： 决策与规划。核心： 极简 System Prompt。AI 仅知道它是一个运维专家，拥有 4 个工具。L4: Interface Layer (React / WebOS)职责： 状态展示与用户确认。功能： 所有的“写”操作必须在这一层由用户进行“物理确认”（Gatekeeper）。3. 四大核心工具 (The Atomic Tools)为了保持极简与高性能，VentoOS AI 仅暴露四个底层原语，所有复杂运维能力通过这四个工具组合实现：工具逻辑实现 (Rust Backend)Harness 约束Readvfs::read_to_string禁止读取系统敏感路径（如 /etc/shadow），支持大文件流式切片。Writevfs::atomic_write写前备份，支持回滚。禁止覆盖系统关键配置文件。Editvfs::patch_apply仅允许基于行号或语义块的局部修改，避免 LLM 重写整个大文件导致的 Token 浪费。Bashpty::execute在受限的伪终端中运行。超时控制（Timeout）与交互劫持。4. 记忆系统：智能状态管理 (Stateful Memory)为了解决长对话导致的性能下降，采用 阶梯式记忆压缩 方案：A. 短期记忆 (Working Memory)存储： 内存（Zustand + Rust State）。内容： 最近 10 轮对话的原始上下文。特性： 保证 100% 的召回精度，用于处理当前任务。B. 智能压缩层 (Session Compression)触发： 当 Token 达到阈值（如 4k）时启动。逻辑：提取 Intent (意图) 与 Outcome (结果)。丢弃中间冗长的日志输出和失败尝试。使用 Rust 实现的摘要算法（结合 LLM）生成“会话存根”。C. 长期记忆 (Long-term RAG)存储： 向量数据库（本地 Qdrant / SurrealDB）。内容： 历史成功的运维方案、特定的 K8s 集群拓扑、用户习惯。检索： 基于语义搜索，仅在必要时作为“背景知识”注入。5. 极简 System Prompt 规范我们不使用“你是一个温柔且乐于助人的...”这类废话。Harness 要求指令必须是功能性的。PlaintextIdentity: VentoOS SRE Assistant.
Environment: Browser-based MacOS style OS, Rust-backed VFS/PTY.
Constraint: You must only use the provided 4 tools. 
Constraint: For any destructive action, describe the impact first.
Goal: Efficient, high-performance DevOps operations.
6. 开发需求与技术路线 (Roadmap)第一阶段：Rust 内核重构 (The Foundation)实现 Rust 版 PTY 调度器，支持多会话并发。构建 VFS 抽象层，对接本地文件系统与远程服务器。交付物： 一个不带 AI 的、可编程的 Rust CLI 环境。第二阶段：Harness 策略引擎 (The Shield)开发 Command-Validator，实现对 Bash 指令的词法分析。建立基于 JWT 的 Session 隔离机制。第三阶段：Agent-Loop 与记忆压缩 (The Brain)集成 Rig 或 genai 框架，跑通 ReAct 循环。实现基于 Token 计数的自动压缩算法。交付物： 具备 Read/Write/Edit/Bash 能力的 AI 助手。7. 性能指标约束 (SLA)TTFT (首字延迟)： 本地模型 < 200ms，远程模型 < 800ms。VFS IO 延迟： Rust 层处理开销 < 5ms。内存占用： 单个 Agent 会话内存消耗 < 50MB（不含模型）。鲁棒性： 即使 LLM 输出乱码，Harness 层必须能够捕获解析错误并优雅重置会话，而不导致 VentoOS 崩溃。
