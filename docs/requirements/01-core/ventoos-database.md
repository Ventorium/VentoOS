# VentoOS - 数据库模块设计

## 1. 模块定位

数据库应用负责承接关系型数据库连接、对象管理、SQL 工作区、数据维护、导入导出与可视化分析，目标体验接近 Navicat，但和 VentoOS 的任务系统、AI、K8s 直连能力深度整合。

第一阶段必须支持：

* PostgreSQL
* MySQL
* SQLite

## 2. 连接模型

### 2.1 连接能力

每个连接至少包含：

* 连接名称
* 类型
* 分组
* 标签
* 收藏状态
* 主机 / 端口 / 文件路径
* 用户名
* 凭据引用
* 默认数据库
* 字符集
* 排序规则
* 隧道配置
* 测试状态
* 最近使用时间

### 2.2 连接组织能力

必须支持：

* 分组
* 标签
* 搜索
* 收藏
* 最近连接
* 复制连接
* 导入 / 导出连接定义

### 2.3 隧道支持

第一阶段必须支持：

* 直连
* SSH 隧道
* HTTP 隧道

说明：

* SSH 隧道用于跳板机场景。
* HTTP 隧道可用于未来接入平台代理或网关代理方案。
* 隧道必须由 Rust Core 管理生命周期。

### 2.4 连接测试

必须支持：

* 显式测试连接。
* 返回失败原因，例如认证失败、网络超时、隧道失败、数据库不存在。
* 可选择“测试并保存”。

## 3. 信息架构

推荐布局：

* 左侧：连接分组、数据库对象树。
* 中间：SQL 编辑器、结果页签、数据表视图。
* 右侧：对象属性、DDL、索引、约束、统计信息。

## 4. 连接后的工作区能力

### 4.1 多数据库选择

连接打开后必须支持：

* 查看当前实例可访问数据库列表。
* 切换数据库。
* 创建数据库。
* 修改数据库属性。
* 删除数据库。

数据库级操作至少要支持：

* 字符集查看与修改。
* 排序规则查看与修改。
* 数据库导入导出入口。

### 4.2 Schema / 对象浏览

至少支持浏览：

* Databases
* Schemas
* Tables
* Views
* Materialized Views
* Indexes
* Functions / Procedures
* Triggers
* Sequences

不同数据库类型可以做适配，但统一浏览结构必须成立。

## 5. SQL 工作区

### 5.1 编辑器

必须支持：

* 多标签页。
* 多连接并行。
* 语法高亮。
* 自动补全。
* 执行选中 SQL / 执行全部。
* 历史记录。
* 收藏 SQL。
* 执行计划入口。

### 5.2 查询结果

必须支持：

* 表格查看。
* 排序、筛选、分页。
* 复制单元格 / 行 / 结果集。
* 导出 CSV / JSON / SQL。
* 错误高亮与定位。

## 6. 数据库维护能力

### 6.1 数据库级

* 创建数据库。
* 删除数据库。
* 修改数据库名称。
* 修改字符集。
* 修改排序规则。
* 导入数据库。
* 导出数据库。

### 6.2 表维护

必须支持：

* 新建表。
* 修改表结构。
* 删除表。
* 重命名表。
* 查看与编辑字段、主键、索引、唯一约束、外键。
* 导出建表 SQL。
* 查看表大小、行数估计、更新时间。

### 6.3 数据维护

必须支持：

* 表数据浏览。
* 行级增删改查。
* 条件过滤。
* 批量编辑。
* 插入记录。
* 删除记录。
* 导出结果。

说明：

* 行级编辑必须在风险较低的体验下完成，例如显式编辑模式与保存确认。

## 7. 导入导出能力

### 7.1 导入

第一阶段至少支持：

* SQL 文件导入。
* CSV 导入。

### 7.2 导出

第一阶段至少支持：

* 数据库导出为 SQL。
* 表导出为 SQL / CSV / JSON。
* 查询结果导出。

导出任务必须进入任务中心，可保存到 VFS 挂载点。

## 8. ER 图能力

至少需要：

* 根据表结构和外键关系生成 ER 图。
* 支持导出图片或可分享文件。
* 支持按 Schema 或选中表范围导出。

## 9. K8s 联动

数据库模块必须支持以下打开方式：

* 从连接中心直接打开。
* 从 Kubernetes Service / Pod / Ingress 识别后打开。
* 从 AI 对话中打开。

K8s 联动打开时，系统应：

* 自动识别数据库类型。
* 自动建立所需代理链路。
* 生成临时连接。
* 提示是否保存为长期连接。

## 10. AI 联动

应向 AI 暴露：

* 连接测试。
* 数据库列表。
* 表结构查看。
* SQL 执行。
* 数据导出。
* ER 图导出。

高风险操作如删库删表必须确认。

## 11. 性能要求

* 大表浏览必须分页。
* 对象树惰性加载。
* 查询结果流式返回或分批加载。
* 导入导出走后台任务。

## 12. 安全要求

* 凭据由 Rust Core 持有。
* 查询历史与收藏 SQL 需要本地持久化。
* 高风险 DDL / DML 必须确认或开启安全模式。
