# VentoOS - UI / UX 设计

## 1. 设计目标

VentoOS 的界面不是简单模仿 macOS 皮肤，而是借鉴 macOS 在桌面系统中的空间感、层级感、动效节奏和系统反馈机制，构建一个适合专业运维工具的 WebOS。

核心要求：

* 看起来像桌面，不像普通后台页面。
* 复杂但不混乱，信息密度高但层级清晰。
* 动效真实自然，不喧宾夺主。
* 支持长期驻留、多任务并行与状态恢复。

## 2. 视觉语言

### 2.1 基本风格

* 类 macOS 风格。
* 毛玻璃、半透明、背景采样模糊。
* 壁纸驱动氛围，桌面层和窗口层形成深度差。
* 中高圆角、柔和阴影、轻描边。
* 色彩整体克制，强调色用于状态、选择、任务结果与风险提示。

### 2.2 材质定义

需要至少区分三层材质：

* Desktop Material：桌面层，强调壁纸与空间感。
* Surface Material：窗口与面板层，透明度适中，保证可读性。
* Overlay Material：通知、命令面板、右键菜单、对话框，模糊更强、对比更高。

### 2.3 主题能力

* 自动模式：跟随系统或时间切换浅色/深色。
* 浅色模式。
* 深色模式。
* 壁纸切换与动态壁纸能力预留。

## 3. 总体布局

### 3.1 顶部系统栏

必须包含：

* 当前激活应用名称。
* 全局菜单入口。
* 系统时间与状态。
* 活跃连接状态摘要。
* 后台任务状态入口。
* 通知入口。

顶部栏的菜单需要具备“系统级操作”与“应用级操作”双层能力，类似 macOS 菜单栏概念。

### 3.2 中央桌面区

* 用于承载多窗口。
* 支持壁纸与轻量桌面小组件扩展位。
* 支持拖放文件到应用窗口。
* 支持窗口阴影、投射与吸附效果。

### 3.3 底部 Dock

布局要求：

* 左侧：应用启动器、固定应用。
* 中间：已打开窗口与应用实例。
* 右侧：AI 助手入口、任务中心快捷入口。

交互要求：

* Hover 放大。
* 激活态高亮。
* 最小化后的窗口保留在 Dock 中。
* 支持右键菜单，例如新建窗口、关闭其它窗口、固定到 Dock。

### 3.4 右上通知中心

* 默认使用自定义通知中心。
* 若用户授权浏览器原生通知，则可以同步发送系统通知。
* 通知必须按来源分类：系统、连接、任务、Agent、应用。

## 4. 窗口系统设计

### 4.1 窗口基础能力

* 可拖拽。
* 可缩放。
* 可最小化、最大化、关闭。
* 支持交通灯按钮。
* 支持记忆位置和尺寸。
* 支持多标签页应用内部布局。
* 支持同一应用多窗口实例。

### 4.2 窗口形态

* Standard Window：标准工作窗口。
* Utility Window：辅助窗口，例如连接测试、端口映射面板。
* Modal Window：高风险确认或关键编辑器。
* Floating Panel：命令面板、快速预览、资源属性面板。

### 4.3 窗口生命周期

* 打开有放大淡入或从触发源展开的动画。
* 最小化有吸附回 Dock 的动画。
* 关闭有淡出和回收动效。
* 聚焦窗口在阴影、透明度、顶部栏信息上有明显反馈。

### 4.4 状态恢复

刷新或重启后至少恢复：

* 打开的应用与窗口。
* 窗口位置、尺寸、层级。
* 当前标签页和选中的资源。
* 编辑器草稿。
* 当前连接上下文和筛选器。

## 5. 应用级 UI 原则

### 5.1 Kubernetes 应用

* 默认采用三栏或双栏工作区。
* 左侧为集群/命名空间/资源树。
* 中间为资源列表。
* 右侧为详情、日志、YAML、事件、关联资源等标签区域。

### 5.2 数据库应用

* 左侧连接与数据库对象树。
* 中间 SQL 编辑器与结果标签页。
* 右侧对象详情、DDL、统计或数据编辑器。

### 5.3 Redis 应用

* 左侧连接与 DB 切换。
* 中间 Key 列表。
* 右侧 Value 编辑器、元数据、TTL、命令结果。

### 5.4 资源管理器

* 顶部路径栏、快捷操作栏。
* 左侧收藏与挂载点。
* 中间文件列表或网格。
* 右侧预览与属性面板。

## 6. 全局系统能力

### 6.1 全局任务中心

需要展示：

* 正在执行的任务。
* 任务进度、状态、日志。
* 可取消、重试、查看详情。
* Agent 触发与用户触发来源标记。

### 6.2 全局 AI 入口

* 固定在 Dock 右侧。
* 可以打开独立 AI 助手窗口。
* 也可以以侧边面板模式挂靠在当前应用窗口。
* 必须感知当前上下文，例如当前窗口、当前资源、当前选区。

### 6.3 全局命令面板

支持：

* 打开应用。
* 搜索资源。
* 执行动作。
* 调用 AI。
* 跳转最近窗口与最近任务。

## 7. 动效原则

* 打开/关闭窗口：120ms-220ms。
* 面板展开/收起：100ms-180ms。
* Dock hover：80ms-140ms。
* 通知出现/消失：140ms-220ms。

原则：

* 动效用于解释空间关系和状态变化。
* 动效不能阻断高频工作流。
* 批量任务和流式日志场景避免过多动画干扰。

## 8. 交互原则

* 少跳转，多窗口，多上下文并行。
* 操作应尽量在当前场景完成。
* 所见即所得，编辑与结果尽量同屏。
* 危险操作明确分级。
* 所有耗时操作要可感知。
* 支持撤销的操作优先支持撤销。

## 9. 设计 Token 建议

* `radius.window = 16px`
* `radius.panel = 14px`
* `radius.control = 10px`
* `blur.desktop = 12px`
* `blur.surface = 20px`
* `blur.overlay = 28px`
* `shadow.window = soft-xl`
* `spacing.base = 8px`

## 10. 响应式原则

虽然是 WebOS，仍需支持不同屏幕：

* 宽屏优先。
* 笔记本标准分辨率可完整使用。
* 小屏场景下支持窗口自动吸附与简化布局。
* 触控支持不是第一阶段重点，但要避免完全无法扩展。
