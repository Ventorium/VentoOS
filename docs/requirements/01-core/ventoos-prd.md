# VentoOS - 产品总体描述（PRD）

## 1. 产品定位

VentoOS 是一个本地优先、浏览器承载、面向运维与基础设施管理的 WebOS。它不是多个工具页面的集合，而是一套在用户电脑上运行的“统一工作桌面”，目标是在一个系统内整合 Kubernetes、数据库、Redis、资源管理和 AI Agent 协作能力。

产品体验上，VentoOS 要接近 macOS 的视觉和交互风格；系统能力上，VentoOS 要像 Lens + Navicat + Tiny RDM + Finder + AI Agent 编排层的组合，但通过统一连接模型、统一任务系统和统一权限边界把这些能力重新组织起来。

## 2. 产品愿景

让运维、后端、SRE 和技术负责人在一个本地系统中完成大部分日常基础设施工作，并让 AI 能真正“操作系统”，而不是仅做问答。

## 3. 核心目标

### 3.1 效率目标

* 统一 Kubernetes、数据库、Redis、文件资源、AI 助手的入口与交互模型。
* 减少跨工具切换、重复登录、重复配置、重复端口映射等手工步骤。
* 通过自动发现与上下文继承，让用户从“看到资源”到“完成操作”的路径尽可能短。

### 3.2 体验目标

* 提供类 macOS 的桌面感体验，包括壁纸、毛玻璃、透明、窗口交通灯、自然动画、全局任务与通知。
* 保证状态恢复能力，刷新后窗口布局、应用会话、连接上下文、草稿与任务状态可恢复。
* 保证专业工具应有的密度与效率，不做过度娱乐化的“伪桌面”。

### 3.3 技术目标

* 以前端 React + 本地 Rust Core 的模式实现高性能、高可控、低延迟的系统交互。
* 让所有资源能力沉淀为系统级 API / Tool，供 UI 和 AI 统一调用。
* 前期接入本机成熟 Agent 引擎，避免重复造轮子。

## 4. 核心理念

* 本地优先（Local First）：数据、凭据、缓存、状态、历史任务默认保存在用户本机。
* 资源优先（Resource First）：系统围绕连接、资源、对象关系、任务和操作历史组织，而非围绕单页流程。
* 桌面优先（Desktop First）：每个功能模块都是应用，窗口是一级交互单元。
* 可编排（Composable）：任何能力都应可被用户手动触发、应用内部组合、任务系统调度、AI 通过 Tool 调用。
* AI 原生（AI Native）：AI 是系统操作入口与自动化执行层，不是外挂聊天框。

## 5. 目标用户

* DevOps 工程师
* SRE
* 后端工程师
* 平台工程师
* 小团队技术负责人

## 6. 核心使用场景

### 6.1 Kubernetes 运维

* 登录 Teleport 或直接加载 kubeconfig，选择目标集群与命名空间。
* 查看资源总览、节点负载、工作负载状态、日志、事件、YAML、终端、端口映射。
* 从 K8s 资源直接打开数据库或 Redis 连接，而不是手动构建 port-forward 链路。

### 6.2 数据库开发与运维

* 维护 PostgreSQL、MySQL、SQLite 连接和分组。
* 通过 SSH / HTTP 隧道连接数据库。
* 执行 SQL、多标签页分析、导入导出、表维护、数据维护、ER 图导出。

### 6.3 Redis 运维

* 管理 Redis / Redis Sentinel / Redis Cluster 连接。
* 浏览 Key、编辑复杂值、执行命令、查看内存热点、TTL、慢日志与连接信息。
* 从 Kubernetes 服务快速建立直连或临时代理连接。

### 6.4 文件与资源协同

* 将本地目录、SFTP、FTP、SMB、S3、网盘资源统一挂载到 VFS。
* 用 Finder 式交互完成浏览、复制、移动、上传、下载、预览、批量任务。
* 把 Pod 文件系统、远端主机文件系统、对象存储视为统一资源。

### 6.5 AI 辅助执行

* 用户通过文本、语音、命令面板描述任务。
* AI 根据当前窗口上下文、连接上下文、资源选中状态、历史任务选择合适 Tool 执行。
* 高风险操作进行确认，执行结果回写到任务中心和具体应用窗口。

## 7. 第一阶段功能范围

### 7.1 WebOS Shell

* 桌面、壁纸、顶部菜单栏、底部 Dock、通知中心、任务中心、AI 入口。
* 多窗口、多应用、多工作区、窗口状态恢复。
* 应用启动、关闭、最小化、最大化、聚焦、拖拽、缩放、层级管理与动画。

### 7.2 Kubernetes 应用

* 多集群管理。
* 原生 kubeconfig 接入。
* Teleport 登录后拉取临时 kubeconfig 并接入集群。
* 资源总览。
* 节点管理、工作负载管理、配置类资源、网络类资源、存储类资源、权限类资源、CRD、ArgoCD 资源。
* YAML 编辑器、日志、Shell/Exec、Port Forward、事件、资源关系导航。

### 7.3 数据库应用

* PostgreSQL、MySQL、SQLite 支持。
* 连接分组、收藏、搜索、标签、最近使用。
* 直连、SSH 隧道、HTTP 隧道。
* 连接测试。
* 数据库对象浏览、DDL/DML 操作、导入导出、ER 图、SQL 多标签页。

### 7.4 Redis 应用

* Standalone、Sentinel、Cluster 模式支持。
* 连接分组、SSH/HTTP 隧道、连接测试。
* 数据库切换、Key 浏览、Value 编辑、命令执行、批量删除与迁移、TTL 管理、监控与诊断。

### 7.5 资源管理器（VFS）

* local / ssh(sftp) / ftp / smb / s3 / 网盘挂载。
* 统一路径模型、统一文件与目录能力、统一元数据与任务模型。
* 跨挂载点复制、移动、上传、下载、预览、搜索。

### 7.6 AI 助手应用

* 文本与语音输入。
* Agent 引擎适配。
* Tool/Skill 注册。
* 任务规划、执行确认、结果回写。
* 可在系统应用上下文中触发操作。

## 8. 核心差异点

* K8s → DB / Redis 一键直连，而不是要求用户手动完成端口映射和连接配置。
* 统一 VFS，屏蔽多协议差异，让“资源管理器”成为系统级基础设施。
* AI 可操作整个系统，并可调用系统注册能力，而不是孤立聊天工具。
* WebOS Shell 提供桌面化的多窗口运维体验，不把复杂场景压缩成单页路由。
* 本地 Rust Core 承担高性能协议交互和任务执行，保证复杂场景的流畅性与安全性。

## 9. 关键需求原则

* 所有外部资源访问默认经由 Rust Core。
* 所有写操作默认进入任务系统并可观察。
* 所有连接对象都有统一的生命周期、凭据策略和健康状态。
* 所有应用至少支持“独立打开窗口”和“从其他应用联动打开窗口”两种入口。
* 所有 AI Tool 都必须映射到明确的系统能力与权限边界。

## 10. 非目标（第一阶段不做）

* SaaS 云托管版。
* 多用户实时协作。
* 完整插件市场。
* 企业级 RBAC / SSO / 审批流体系。
* 通用 CI/CD 编排平台。

## 11. 关键成功指标

### 11.1 用户价值指标

* 覆盖 50% 以上日常运维高频操作。
* 连接建立和问题排查的平均步骤数下降 70%。
* 至少 30% 的日常查询或维护任务可通过 AI 成功辅助完成。

### 11.2 产品质量指标

* 桌面 Shell 在中等规模数据量下保持流畅交互。
* K8s 资源列表、日志、数据库对象浏览、Redis Key 浏览具备可用的增量加载与缓存机制。
* 所有高风险 AI 操作都具备确认、审计与结果可追踪性。

## 12. 版本建议

本项目持续迭代开发，不采用固定里程碑划分。
