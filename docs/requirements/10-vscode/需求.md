## 1. 总体目标与约束

### 1.1 目标

- 在 VentoOS 窗口中提供完整的代码编辑体验，UI/UX 尽可能接近 VS Code
- 支持本地和远程文件编辑（通过 VFS 统一访问 local/sftp/ftp/smb/s3/webdav）
- 提供 LSP 语言服务、Git 集成、集成终端、搜索替换、主题切换等核心能力
- 作为 VentoOS 的内置应用，复用 WebOS 的窗口管理、通知、任务系统

### 1.2 技术约束

| 约束项 | 说明 |
|---|---|
| 前端框架 | React 19 + TypeScript，不使用 VS Code 的原生 DOM 框架 |
| 编辑器引擎 | Monaco Editor（@monaco-editor/react） |
| 终端组件 | xterm.js（复用已有 WebShell） |
| 后端 | Rust/Axum，通过 HTTP REST + WebSocket 通信 |
| 文件系统 | 通过 VFS 抽象层，支持多种存储后端 |
| 状态管理 | Zustand（编辑器级 store） |
| 不使用 | VS Code 源码、Electron、Tauri IPC、Node.js Extension Host |
| LSP/Git 限制 | 仅支持 `local` 类型 mount，远程 mount（SFTP/S3 等）降级为无 LSP、无 Git 模式 |
| 大文件策略 | >2MB 禁用 minimap/tokenization/bracket matching；>10MB 降级为只读纯文本模式 |
| 浏览器限制 | `Ctrl+W`/`Ctrl+N`/`Ctrl+T`/`Ctrl+L`/`Ctrl+Shift+T` 等被浏览器拦截，需使用替代快捷键 |

### 1.3 与现有系统的集成点

| 系统 | 集成方式 |
|---|---|
| 窗口管理 | 通过 `useWindowActions` 操作窗口标题、状态 |
| 应用菜单 | 通过 `registerAppMenus` 注册到 TopBar |
| 通知系统 | 通过 `useNotificationStore` 发送通知 |
| 文件打开 | 通过 `useFileOpenMenu` + `VfsFilePickerModal` |
| 设置系统 | 读取 VentoOS 全局主题设置 |
| 应用存储 | 通过 `/api/storage/{app_id}/{key}` 持久化编辑器配置 |
| WebShell | 复用 `web/src/shell/WebShell` 组件 |
| 文件图标 | 复用 `web/src/kernel/apps/file-icons.ts` |

### 2.2 状态管理

使用 Zustand store 管理编辑器状态，拆分为多个独立 store：

```typescript
// 编辑器核心 store
useEditorStore: {
  tabs: FileTab[]
  activeTabId: string | null
  tabGroups: TabGroup[]         // 分栏编辑
  dirtyTabs: Set<string>
}

// 工作区 store
useWorkspaceStore: {
  workspace: WorkspaceRoot | null
  fileTree: TreeNode[]
  expandedDirs: Set<string>
  selectedFile: string | null
}

// 面板/布局 store
useLayoutStore: {
  sidebarVisible: boolean
  sidebarWidth: number
  sidebarView: 'explorer' | 'search' | 'git' | 'extensions'
  panelVisible: boolean
  panelHeight: number
  panelView: 'terminal' | 'output' | 'problems'
  auxiliarySidebarVisible: boolean
}

// Git store
useGitStore: {
  status: GitFileStatus[]
  branch: string
  ahead: number
  behind: number
  staged: string[]
  unstaged: string[]
}

// 搜索 store
useSearchStore: {
  query: string
  results: SearchResult[]
  replaceText: string
  isRegex: boolean
  isCaseSensitive: boolean
  isWholeWord: boolean
  includePattern: string
  excludePattern: string
}

// 终端 store
useTerminalStore: {
  terminals: TerminalInstance[]
  activeTerminalId: string | null
}

// LSP store
useLspStore: {
  diagnostics: Map<string, Diagnostic[]>
  activeServers: LspServerInfo[]
}

// 编辑器配置 store
useEditorConfigStore: {
  fontSize: number
  tabSize: number
  wordWrap: 'on' | 'off' | 'wordWrapColumn'
  minimap: boolean
  lineNumbers: 'on' | 'off' | 'relative'
  theme: string
  // ...更多 Monaco 配置
}
```

## 5. 文件树 (Explorer)

### 5.1 树结构

文件树显示当前打开的 workspace 目录结构，支持：

- **延迟加载**：仅在展开目录时加载子节点（通过 VFS API `listVfsDir`）
- **排序规则**：文件夹在前，文件在后；同类按名称字母排序（大小写不敏感）
- **缩进层级**：每层缩进 16px，缩进区域显示连接线（indent guides）
- **文件图标**：每个节点前显示对应文件类型的图标（接入 `getFileIconByName`）
- **文件夹图标**：展开/折叠状态分别用向下/向右箭头 + 文件夹图标
- **隐藏文件**：默认隐藏 `.` 开头的文件，可通过设置切换显示
- **Loading 状态**：展开目录时，显示 loading spinner 直到子节点加载完成

### 5.2 交互行为

| 操作 | 行为 |
|---|---|
| 单击文件 | 在编辑器中**预览**（斜体标签名）；再单击其他文件时替换预览标签 |
| 双击文件 | 在编辑器中**打开**（固定标签） |
| 单击已打开的文件 | 切换到对应标签 |
| 单击文件夹 | 展开/折叠 |
| 拖拽文件 | 移动文件到目标文件夹 |
| 拖拽文件夹 | 移动文件夹到目标文件夹 |
| 从桌面拖入文件 | 上传文件到当前目录（VFS upload API） |
| 键盘 ↑/↓ | 上下移动高亮 |
| 键盘 Enter | 打开文件 / 展开文件夹 |
| 键盘 F2 | 重命名 |
| 键盘 Delete | 删除（需确认） |
| 键盘 → | 展开文件夹 |
| 键盘 ← | 折叠文件夹 / 跳到父级 |
| 键盘字母快速输入 | 快速定位到匹配名称的节点（type-ahead find） |

### 5.3 预览模式 (Preview)

VS Code 的预览模式行为：
- 单击文件打开为**预览**，标签名显示为*斜体*
- 预览标签只保留一个，单击另一个文件时替换
- 双击文件 / 在预览标签中编辑 / 双击预览标签 → 转为**固定**标签（正常字体）
- 固定标签不会被预览替换

## 6. 文件图标系统

### 6.1 文件图标

接入 VentoOS 已有的 `getFileIconByName()` 函数（位于 `web/src/kernel/apps/file-icons.ts`），为文件树和标签页提供类型化图标。

文件树和标签页中的每个文件节点前渲染对应图标：

```typescript
import { getFileIconByName } from '@/kernel'

// 使用方式
const iconInfo = getFileIconByName(filename)
// iconInfo.icon → Lucide React Component
// iconInfo.color → 十六进制颜色值
```

### 6.2 文件夹图标

文件夹使用统一图标，根据展开状态区分：
- 折叠状态：`ChevronRight` + `Folder` 图标（颜色 `#dcb67a`）
- 展开状态：`ChevronDown` + `FolderOpen` 图标（颜色 `#dcb67a`）

特殊文件夹名称可以使用差异化图标颜色（可选增强）：

| 文件夹名 | 图标颜色 |
|---|---|
| `src` | `#42a5f5` |
| `node_modules` | `#8d6e63` |
| `.git` | `#ef5350` |
| `test` / `tests` / `__tests__` | `#66bb6a` |
| `build` / `dist` / `out` | `#ff9800` |
| `public` / `static` / `assets` | `#ab47bc` |

### 6.3 标签页图标

编辑器标签页也需要显示文件类型图标：
- 在标签文字左侧显示对应的文件图标（使用 `getFileIconByName`）

- 支持 glob include/exclude 过滤
- 二进制文件自动跳过（前 8KB 含 `\0` 则跳过）

- 流式返回结果，前端使用 `ReadableStream` 处理

### 9.11 后端 Git API 设计

所有 Git API 路径前缀: `/api/code/git`

**安全约束**：
- 所有 Git 命令只在经过验证的 workspace 目录中执行
- 所有参数使用 `Command::arg()` 逐个传递，禁止使用 `shell=true` 或 `sh -c`
- 路径参数进行 `canonicalize()` + 前缀校验（必须在 mount root 内）
- 分支名/标签名只允许 `[a-zA-Z0-9_/.-]`
- `git clone` URL 只允许 `https://`、`http://`、`ssh://`、`git://` 协议
- 不支持 `--force` push
- 不允许执行任意 git 子命令
- `git status` 使用 `--porcelain=v2` 获得结构化输出
- `amend` 操作需额外确认标志

```typescript
// 前端 API 接口
interface GitApi {
  // 初始化
  init(mountId: string, path: string): Promise<void>
  detect(mountId: string, path: string): Promise<{ isGitRepo: boolean }>
  
  // 状态
  status(mountId: string, path: string): Promise<GitStatus>
  
  // 暂存
  add(mountId: string, path: string, files: string[]): Promise<void>
  reset(mountId: string, path: string, files: string[]): Promise<void>
  
  // 提交
  commit(mountId: string, path: string, message: string, amend?: boolean): Promise<void>
  
  // 分支
  getBranches(mountId: string, path: string): Promise<GitBranch[]>
  checkout(mountId: string, path: string, branch: string): Promise<void>
  createBranch(mountId: string, path: string, name: string, from?: string): Promise<void>
  deleteBranch(mountId: string, path: string, name: string): Promise<void>
  
  // 远程
  push(mountId: string, path: string): Promise<void>
  pull(mountId: string, path: string): Promise<void>
  fetch(mountId: string, path: string): Promise<void>
  
  // Diff
  diff(mountId: string, path: string, file: string): Promise<GitDiff>
  diffStaged(mountId: string, path: string, file: string): Promise<GitDiff>
  
  // Stash
  stash(mountId: string, path: string, message?: string): Promise<void>
  stashPop(mountId: string, path: string): Promise<void>
  stashList(mountId: string, path: string): Promise<StashEntry[]>
  
  // 日志
  log(mountId: string, path: string, limit?: number): Promise<GitLogEntry[]>
  
  // Blame（支持局部 blame 避免大文件性能问题）
  blame(mountId: string, path: string, file: string, startLine?: number, endLine?: number): Promise<BlameLine[]>
  
  // 丢弃
  discardChanges(mountId: string, path: string, files: string[]): Promise<void>
}
```

**后端 Rust 实现参考**（sidex `git.rs` 模式）：

```rust
fn run_git(workdir: &str, args: &[&str]) -> Result<String, String> {
    let output = Command::new("git")
        .current_dir(workdir)
        .args(args)
        .output()
        .map_err(|e| format!("Failed to execute git: {}", e))?;
    if output.status.success() {
        Ok(String::from_utf8_lossy(&output.stdout).to_string())
    } else {
        Err(String::from_utf8_lossy(&output.stderr).trim().to_string())
    }
}
```

## 10. LSP 语言服务

### 10.1 概述

通过后端运行 LSP（Language Server Protocol）语言服务器进程，并通过 WebSocket 桥接 LSP 的 JSON-RPC 消息到前端 Monaco Editor，提供：

- **自动补全** (completion)
- **悬停提示** (hover)
- **转到定义** (go to definition)
- **查找引用** (find references)
- **符号搜索** (workspace symbol)
- **诊断** (diagnostics / lint errors)
- **签名帮助** (signature help)
- **代码操作** (code actions / quick fix)
- **重命名** (rename)
- **格式化** (formatting)

### 10.2 架构


### 10.4 前端 LSP Client

使用 `monaco-languageclient` npm 包或自定义实现 LSP Client：

```typescript
// LSP WebSocket 连接
const ws = new WebSocket(`/ws/code/lsp/${language}?mount_id=xxx&root_path=/workspace`)

// 发送请求
ws.send(JSON.stringify({
  jsonrpc: "2.0",
  id: 1,
  method: "textDocument/completion",
  params: {
    textDocument: { uri: "file:///workspace/src/App.tsx" },
    position: { line: 10, character: 15 }
  }
}))

// 接收通知（诊断）
ws.onmessage = (event) => {
  const msg = JSON.parse(event.data)
  if (msg.method === "textDocument/publishDiagnostics") {
    // 更新 Monaco 中的 markers
    monaco.editor.setModelMarkers(model, 'lsp', convertDiagnostics(msg.params.diagnostics))
  }
}
```

### 10.7 后端 LSP Bridge

**限制**：LSP 仅支持 `local` 类型 mount（LSP 服务器需直接访问文件系统）。

**实例管理策略**：
- 同一 workspace + 同一语言共享一个 LSP Server 实例（引用计数）
- 多个编辑器窗口打开同一 workspace 复用同一 LSP 实例
- 所有 WebSocket 客户端断开后，LSP 进程空闲 60 秒后回收
- LSP 命令只允许白名单内的可执行文件（不允许用户配置任意命令）

## 13. 快捷键系统 (Keybindings)

### 13.1 适配 WebOS 的快捷键调整原则

由于运行在浏览器中,部分系统级快捷键无法拦截。以下是调整规则：

1. **浏览器保留快捷键不可用**：Ctrl+T (新标签), Ctrl+W (关窗), Ctrl+N (新窗口), Ctrl+L (地址栏) — 这些在浏览器中被系统拦截
2. **VentoOS 全局快捷键优先**：如果 WebOS Shell 已注册了某快捷键，编辑器不重复注册
3. **Mac 适配**：Mac 上使用 ⌘ 替代 Ctrl
4. **冲突处理**：编辑器聚焦时，编辑器快捷键优先；编辑器外部（如文件树聚焦）使用文件树快捷键

## 19. 文件监控 (File Watcher)

### 19.1 概述

### 19.2 行为

| 事件 | 编辑器反应 |
|---|---|

```typescript
// 连接 watch WebSocket
const ws = new WebSocket(

)
ws.onmessage = (event) => {
  const changes: FileChangeEvent[] = JSON.parse(event.data)
  // 处理变更
}
```

## 20. 状态持久化

### 20.1 需要持久化的状态

编辑器状态应在关闭窗口后恢复（使用 `/api/storage/monaco-editor/{key}` 存储）：

**注**：存储 key 使用 `mountId:rootPath` 标识 workspace，与 `windowId` 解耦，确保窗口重建后仍可恢复。

| 状态 | 存储 key | 内容 |
|---|---|---|
| 打开的 workspace | `workspace:{mountId}:{rootPath}` | mountId, rootPath |
| 打开的标签 | `tabs:{mountId}:{rootPath}` | 文件路径列表 + 活跃标签 |
| 光标与滚动位置 | `cursors:{mountId}:{rootPath}` | 每个文件的行/列/scrollTop |
| 侧边栏状态 | `layout:{mountId}:{rootPath}` | 宽度, 可见性, 活跃视图 |
| 面板状态 | `layout:{mountId}:{rootPath}` | 高度, 可见性, 活跃视图 |
| 展开的目录 | `tree:{mountId}:{rootPath}` | 展开目录路径集合 |
| 终端状态 | `terminals:{mountId}:{rootPath}` | 终端名称列表（不含历史输出） |
| 搜索历史 | `search:history` | 最近 20 条搜索词 |
| 最近文件 | `recent-files` | 最近打开的文件/文件夹列表 |
| 编辑器配置 | `settings` | 完整配置 JSON |

### 20.2 恢复流程

1. 窗口打开时，根据传入的 mountId/rootPath 查找持久化数据
2. 如果有 workspace → 恢复文件树 → 恢复打开的标签 → 恢复光标和滚动位置 → 恢复布局 → 恢复终端列表
3. 如果没有 workspace → 显示欢迎页

**恢复失败降级策略**：
- 文件已被删除：跳过该标签，不阻塞其他标签恢复
- Mount 不可用：显示欢迎页，保留持久化数据供后续自动恢复
- 光标位置超出文件长度：光标归零

## 31. 快速打开的后端文件搜索 (Quick Open)

### 31.1 概述

`Ctrl/⌘+P` 的快速打开文件功能需要后端支持文件名/路径搜索 API，以应对大工作区（>10000 文件）。

### 31.2 后端 API

```
GET /api/code/search/files?mount_id=xxx&root_path=/&query=App&max_results=50
```

**响应**:
```json
{
  "files": [
    { "path": "/src/App.tsx", "name": "App.tsx", "score": 95 },
    { "path": "/src/components/AppLayout.tsx", "name": "AppLayout.tsx", "score": 82 },
    ...
  ]
}
```

### 31.3 实现

- 后端使用 `ignore` crate 遍历工作区文件（尊重 `.gitignore`）
- 使用 fuzzy match 算法计算匹配分数（参考 sidex `fuzzy_score()`）
- 加分规则：文件名匹配 > 路径匹配、连续匹配 > 分散匹配、单词边界匹配
- 可选：后端维护文件路径索引缓存，File Watch 时增量更新
- 前端输入 debounce 200ms 后发起搜索

### 32.1 新增后端 API 汇总

#### Git API (`/api/code/git`)

| 方法 | 路径 | 参数 | 返回 | 说明 |
|---|---|---|---|---|
| GET | `/api/code/git/detect` | mount_id, path | `{ is_git_repo: bool }` | 检测是否为 git 仓库 |
| GET | `/api/code/git/status` | mount_id, path | `GitStatus` | 获取工作区 git 状态 |
| GET | `/api/code/git/branch` | mount_id, path | `GitBranchInfo` | 获取分支信息 |
| GET | `/api/code/git/branches` | mount_id, path | `GitBranch[]` | 列出所有分支 |
| GET | `/api/code/git/log` | mount_id, path, limit? | `GitLogEntry[]` | 获取提交日志 |
| GET | `/api/code/git/diff` | mount_id, path, file | `GitDiff` | 获取工作区 diff（大文件>1MB 返回错误） |
| GET | `/api/code/git/diff-staged` | mount_id, path, file | `GitDiff` | 获取已暂存 diff |
| GET | `/api/code/git/stash/list` | mount_id, path | `StashEntry[]` | 列出 stash |
| GET | `/api/code/git/blame` | mount_id, path, file, start_line?, end_line? | `BlameLine[]` | 行级 blame（支持局部） |
| POST | `/api/code/git/init` | mount_id, path | — | 初始化 git 仓库 |
| POST | `/api/code/git/add` | mount_id, path, files[] | — | 暂存文件（files 数组上限 500） |
| POST | `/api/code/git/reset` | mount_id, path, files[] | — | 取消暂存 |
| POST | `/api/code/git/commit` | mount_id, path, message, amend?, confirm_amend? | — | 提交（amend 需 confirm_amend=true） |
| POST | `/api/code/git/checkout` | mount_id, path, target | — | 切换分支/丢弃更改 |
| POST | `/api/code/git/branch/create` | mount_id, path, name, from? | — | 创建分支 |
| POST | `/api/code/git/branch/delete` | mount_id, path, name | — | 删除分支 |
| POST | `/api/code/git/push` | mount_id, path | — | 推送（不支持 --force） |
| POST | `/api/code/git/pull` | mount_id, path | — | 拉取 |
| POST | `/api/code/git/fetch` | mount_id, path | — | 获取远程更新 |
| POST | `/api/code/git/stash` | mount_id, path, message? | — | 暂存到 stash |
| POST | `/api/code/git/stash/pop` | mount_id, path | — | 弹出 stash |
| POST | `/api/code/git/discard` | mount_id, path, files[] | — | 丢弃更改 |
| POST | `/api/code/git/tag` | mount_id, path, name, message? | — | 创建 tag |
| POST | `/api/code/git/tag/delete` | mount_id, path, name | — | 删除 tag |

#### 搜索 API (`/api/code/search`)

| 方法 | 路径 | 参数 | 返回 | 说明 |
|---|---|---|---|---|
| GET | `/api/code/search/files` | mount_id, root_path, query, max_results? | `{ files: FileMatch[] }` | 文件名模糊搜索（Quick Open） |
| POST | `/api/code/search/text` | mount_id, root_path, query, options, timeout_ms? | `SearchResult[]` (流式 NDJSON) | 全文搜索 |
| POST | `/api/code/search/replace-preview` | mount_id, replacements[] | `{ affected_files, total }` | 替换预览 |

#### LSP API (`/ws/code/lsp`)

| 协议 | 路径 | 参数 | 说明 |
|---|---|---|---|
| WebSocket | `/ws/code/lsp?language=xxx&mount_id=yyy&root_path=zzz` | language, mount_id, root_path | LSP JSON-RPC 桥接（仅 local mount） |

#### 辅助 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/code/git/detect` | 检测目录是否为 git 仓库 |

### 32.2 API 数据类型

```typescript
// Git 相关类型
interface GitStatus {
  branch: string
  ahead: number
  behind: number
  staged: GitFileChange[]
  unstaged: GitFileChange[]
  untracked: string[]
}

interface GitFileChange {
  path: string
  status: 'M' | 'A' | 'D' | 'R' | 'C' | 'U'
  oldPath?: string  // 重命名时的原路径
}

interface GitBranch {
  name: string
  current: boolean
  remote?: string
  upstream?: string
}

interface GitBranchInfo {
  current: string
  ahead: number
  behind: number
}

interface GitLogEntry {
  hash: string
  shortHash: string
  author: string
  email: string
  date: string      // ISO 8601
  message: string
}

interface GitDiff {
  original: string   // HEAD 版本的完整内容
  modified: string   // 工作区版本的完整内容
}

interface StashEntry {
  index: number
  message: string
  date: string
}

interface BlameLine {
  line: number
  hash: string
  author: string
  date: string
  content: string
}

// 搜索相关类型
interface TextSearchRequest {
  mount_id: string
  root_path: string
  query: string
  is_regex: boolean
  case_sensitive: boolean
  whole_word: boolean
  include_pattern?: string
  exclude_pattern?: string
  max_results?: number
}

interface TextSearchResult {
  file: string
  matches: TextMatch[]
}

interface TextMatch {
  line: number
  col: number
  length: number
  text: string       // 包含匹配的完整行文本
  preContext?: string // 上文（1-2行）
  postContext?: string // 下文（1-2行）
}

// LSP 相关类型
interface LspServerInfo {
  language: string
  command: string
  status: 'starting' | 'running' | 'stopped' | 'error'
  pid?: number
}
```

## 33. 不实现的功能

以下 VS Code 功能明确**不在本需求范围内**：

| 功能 | 原因 |
|---|---|
| **Debug/调试** | 复杂度极高，需要 DAP 适配器 |
| **账户系统** | VentoOS 有自己的认证系统 |
| **配置同步 (Settings Sync)** | VentoOS 单机运行 |
| **Copilot / AI 内联补全** | VentoOS 有独立的 AI Assistant 应用 |
| **扩展市场 (Extension Marketplace)** | 不实现完整的 VS Code 扩展系统 |
| **Remote Development** | VFS 已提供远程文件访问能力 |
| **Notebooks (Jupyter)** | 超出范围 |
| **Testing Explorer** | 超出范围 |
| **Timeline View** | 超出范围 |
| **多根工作区 (Multi-root Workspace)** | 初期只支持单 workspace root |
| **自定义布局（可移动面板）** | 固定布局即可 |
| **Workspace Trust** | 不需要 |
| **Profiles** | 不需要 |
| **Portable Mode** | 不需要 |
| **CLI 集成 (code 命令)** | 不适用 |
| **Per-language 配置** | 如 `"[python]": { "editor.tabSize": 4 }`，初期不支持 |
