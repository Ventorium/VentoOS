### Database

1. 点击+号无法弹出新增连接的弹框，后续功能皆无法使用
2. 现在的菜单不合理，最左侧应该是分组/连接，连接点开连接上了后才是schema 表，表选择后右侧是表结构/表数据，整体UI要直接仿照 Navicat 来，看参考图@docs/requirements/04-fix/assets/navicat1.png @docs/requirements/04-fix/assets/navicat2.png 
3. rust底层使用 
  - [Sea-Schema](.repos/sea-schema)(探测器): 负责获取这个数据库里现在有什么，实现 Navicat 的左侧树状菜单和表结构预览；
  - [Sea-Query](.repos/sea-query) (生成器): 负责告诉数据库：“我想把这个字段改成补齐长度。”（实现 Navicat 的表结构编辑保存功能）
  - [SQLx](.repos/sqlx) (底层驱动/连接池): 负责把 Rust 连上数据库，并把 SQL 发送出去。作为执行层

  将这些库实际用到的部分全部复制到我们的VentoOS的数据库管理模块中来，可以去除不需要的内容
4. 页面上数据库查询必须得分页，单次最多1000条，前端使用[虚拟滚动](https://github.com/inokawa/virtua)来显示列表

### Redis

1. 无法新增，无法弹框，一样的问题
2. 页面上左侧也应该是分组/连接，连接上之后才是 keys，右侧是值查看，可参考Tiny RDM的应用截图 @docs/requirements/04-fix/assets/tinyrdm1.png @docs/requirements/04-fix/assets/tinyrdm2.png
3. Rust端使用 [redis-rs](.repos/redis-rs) 将其核心需要用到的代码复制到我们的VentoOS的Redis管理工具中来，可以去除不需要的内容
4. 利用 redis-rs 的异步迭代器实现 SCAN，不要直接使用 KEYS *，前端要配合使用virtua虚拟滚动
5. 为了实现类似TinyRDM的把 auth:user:1 这种 Key 显示成文件夹，不要让后端去递归逻辑，这样太慢。后端只管返回原始 Key 列表，由 VentoOS 前端 (React) 利用类似 Trie Tree（前缀树）的算法进行内存级渲染。
6. 利用RESP3 这样可以更优雅地处理 Maps 和 Sets，减少序列化开销。
7. 连接管理架构 (The Connection Bridge)
既然 VentoOS 是 Web 模式，且要接入 K8s 里的 Redis，你需要设计一个 Redis Proxy Actor：

Session 绑定： 每个 Redis 窗口在 Rust 后端对应一个 Actor 或 Task。

隧道抽象：

用户点击 K8s 中的 Redis 服务。

Rust 调用 K8s API 开启 port-forward。

redis-rs 通过本地随机端口建立连接。

实时监控 (Pub/Sub)：

利用 Redis 的 MONITOR 命令。

Rust 后端通过 WebSocket 将实时命令流推送到 VentoOS 的“控制台”窗口。

### Explorer

1. 默认展示的是什么路径的文件？应该直接展示当前系统的根目录/开始
2. 左侧菜单不对，左侧应该是要支持多源的，我的电脑、我增加的其他各种源，比如115网盘、S3对象存储、局域网SMB等。某个服务都有自己的协议，基于VFS实现全平台的Explorer功能。每个存储源都可以通过右键挂载，可配置挂载路径，默认 /mnt/[protocal1/2/3] 路径，每个源都可以配置启动后是否自动挂载。
3. 当前无法展示目录下所有子目录和文件，要改成和MacOS类似的体验，以tree/分栏的形式查看目录和文件
4. 点击文件要可以打开查看，现在是不支持的
5. 支持任意路径文件位置拖动复制、移动，且支持拖动到其它应用，拖过去是文件具体路径，比如拖动到 shell客户端，但是必须得是挂载后的路径或原生路径，因为shell不支持协议路径（s3://path/to）
