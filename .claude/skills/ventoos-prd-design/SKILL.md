# VentoOS 产品原型设计与 PRD 生成

## 技能目标

将**产品截图、参考产品 UI 或功能描述**转化为可指导开发的 PRD 文档，核心原则是：**1:1 还原布局与交互，不遗漏任何用户明确说明需要的功能**。

不定义视觉主题（颜色、字体、图标），这些由 VentoOS 系统级 Design Token 统一管理。

---

## 第一步：明确输入与范围

### 1.1 收集输入材料

用户可能提供以下一种或多种输入：

| 输入类型 | 处理方式 |
|----------|----------|
| **产品截图**（一张或多张） | 逐帧分析布局、组件、交互 |
| **参考产品名称**（如 Lens、pgAdmin） | 基于已知知识分析其核心 UI 模式 |
| **文字描述** | 结合行业常见 UI 模式推断布局 |
| **混合（截图 + 描述）** | 以截图为准，描述作为补充 |

**重要：没有截图的功能也必须覆盖**——基于截图推断整体产品的完整功能集，对未截图的功能依据：
1. 参考产品通用设计规律
2. 用户描述中的功能点
3. 同类工具行业惯例

> 如果无法推断某功能的具体布局，应在 PRD 中标注 `[待确认]` 并描述可能的方案，**不能直接省略**。

### 1.2 询问必要信息（缺失时才问）

如果以下信息不确定，必须先询问用户再开始写 PRD：

- **产品名称与功能定位**（一句话）
- **是现有应用还是新应用？**（决定文档存放目录）
- **有哪些功能确定不需要？**（避免过度还原无用功能）
- **有哪些功能需要特别关注？**（确保重点不遗漏）

## 第二步：确定文档存放位置

### 目录选择规则

```bash
docs/requirements/
├── 01-core/           # 已有：核心架构、K8s、DB、Redis 等
├── 02-connection/     # 已有：连接管理
├── 03-refactor/       # 已有：重构相关
├── 04-fix/            # 已有：Bug 修复
├── 05-vfs/            # 已有：文件系统
├── 06-ai-assistant/   # 已有：AI 助手
├── 07-monitor/        # 已有：监控
├── 08-file-open/      # 已有：文件打开
├── 09-wallpaper/      # 已有：壁纸
├── 10-vscode/         # 已有：VS Code 集成
├── 11-terminal/       # 已有：终端
└── XX-<新产品>/       # 新产品按序号创建
```

**判断逻辑：**

1. 检查用户的产品是否属于现有某个目录（如 K8s 相关 → `01-core`）
2. 如果是现有产品的新功能 → 放到对应目录
3. 如果是全新独立产品 → 查看最大序号，创建 `XX-<产品英文名>/` 新目录

**PRD 文件命名规范：**

```
<产品名>-prd.md                    # 主 PRD 文档
<产品名>-<功能模块>-prd.md         # 模块级 PRD（产品功能较多时拆分）
```

## 第三步：分析截图与产品

### 3.1 截图分析框架

对每张截图，按以下维度逐一分析：

**布局层（必须分析）：**
- 整体区域划分（几列？几行？哪些是固定的，哪些是可变的？）
- 各区域的尺寸/比例（相对或绝对）
- 响应式行为（可拖拽？可折叠？）

**组件层（必须分析）：**
- 识别每个 UI 组件类型（表格、树形列表、表单、面板等）
- 组件的内部结构（表格有哪些列？各列的作用？）
- 组件的状态（正常、悬浮、选中、加载中、空态）

**交互层（必须分析）：**
- 主要操作路径（用户最常见的操作是什么？）
- 触发方式（点击？右键菜单？快捷键？悬浮？）
- 操作反馈（打开什么？跳转到哪？展开什么？）

**信息架构层（必须分析）：**
- 数据模型（这个页面展示的是什么数据？层级是什么？）
- 数据关系（哪些信息是关联的？）

### 3.2 无截图功能的推断原则

当某个功能没有截图时，按以下优先级推断：

1. **同一产品其他截图中的隐含信息**（如设置按钮指向了某个设置页）
2. **用户文字描述**
3. **参考产品（若有）的标准功能集**
4. **同类工具的行业惯例**

推断结果在 PRD 中标注 `[基于推断]`，明确说明推断依据。

## 第五步：PRD 质量检查

在输出 PRD 之前，必须自检以下项目：

### 必须满足

- [ ] **布局完整**：截图中每个可见区域都有对应章节描述
- [ ] **尺寸具体**：关键区域有明确尺寸（px 或 % 均可）
- [ ] **交互完整**：每个交互元素（按钮、右键、快捷键）都有说明
- [ ] **状态全覆盖**：每个组件有加载态、空态、错误态说明
- [ ] **主题规范**：无任何硬编码颜色，全部引用 CSS Variables
- [ ] **未覆盖功能**：没有截图的功能已推断并标注 `[基于推断]` 或 `[待确认]`
- [ ] **文件位置正确**：文档已存放到 `docs/requirements/<正确目录>/` 下

### 常见遗漏检查

- 是否遗漏了右键菜单/上下文菜单？
- 是否遗漏了批量操作（多选）的行为？
- 是否遗漏了键盘快捷键/快捷操作？
- 是否遗漏了拖拽交互？
- 是否遗漏了空态/错误态？
- 是否遗漏了分页、搜索、过滤等通用功能？
- 是否遗漏了移动端/窗口缩小时的响应行为？
- 是否遗漏了数据刷新逻辑（实时？手动？轮询？）？

## 注意事项

1. **不要为了快速完成而省略功能**——宁可标注 `[待确认]` 也不要直接删除
2. **不要定义颜色**——哪怕截图上有明确配色，也全部映射为 CSS Variable 引用
3. **不要凭空发明功能**——未在截图/描述中出现的功能，如果要推断，必须明确标注推断依据
4. **灵活调整文档结构**——不同产品 PRD 结构可以不同，以准确描述该产品为准，不要机械套模板
5. **保持可实现性**——PRD 中描述的组件、交互要在 React + Ant Design 6 + VentoOS 技术栈范围内可实现
